# AgentKanban

由你记录需求、Coding Agent 同步进展的 Windows 桌面任务浮窗。接入本地 MCP 后，Agent 在会修改文件的任务中自动入板，开工时写下计划步骤，此后在阶段完成、受阻和全部完成时更新同一条记录；普通问答不入板，说「不用记」即可跳过。也可以在浮窗里快捷新建，再交给 Agent 接手。

看板按项目展示待办、进行中、受阻和已完成任务。Agent 可以写明下一步、需要你补充的内容和交付物；完成后由你验收。应用本身不调用模型 API。

## 启动

安装构建产物中的 Windows 安装包，然后从开始菜单打开 AgentKanban。安装目录内同时包含 `agentkanban.exe` 和 `agentkanban-mcp.exe`；后者由客户端按需启动，无须单独双击。

交付文件在 `release/`：`AgentKanban_<版本>_x64-setup.exe` 是安装包，`AgentKanban-<版本>-windows-x64.zip` 是免安装包。免安装包解压后运行 `AgentKanban/agentkanban.exe`，仍使用统一的本地数据目录。

默认浮窗约 380 × 520，支持拖动、缩放、置顶开关和明暗主题。收起后显示进行中与受阻数量。关闭按钮隐藏到托盘；通过托盘菜单重新显示或退出。主题、窗口位置、尺寸和展开状态会保留。

详细模式下，每个项目默认展开全部未完成任务；已完成任务（含未验收）变灰并折叠在「已完成」分组。简洁模式保留项目分组，每条任务只显示单行标题和状态，默认显示全部活跃任务；已完成仍折叠。内容超出时在窗口内滚动，任务更新不会强制展开项目。

首次打开全新空看板时，会在「新手教程」项目预设两条明确标注的示例：一条展示进行中、计划步骤和补充要求，一条展示待验收、通过与退回修改。可直接在详情中体验，验收通过后完成项变灰；开始真实工作时通过「新建」选择自己的项目目录。示例可归档，重启不会重新生成；已有用户不会被插入教程。

从旧版本升级时，先退出旧浮窗并停止客户端中的旧 MCP，备份完整数据目录，再替换两个程序并重新连接 MCP。当前数据库为 schema 5（旧版数据库会事务连续迁移），保留旧任务及设置；旧版程序不支持迁移后的数据库。新 MCP 对已有任务的修改要求版本号，更新程序后请在客户端刷新工具说明与同步规则。

## 日常查看

- **简洁模式**：点击顶部深浅色按钮旁的列表按钮，在详细与简洁展示之间切换，重启后记住选择。长标题省略显示，悬停可看全文；点击任务仍打开完整详情。「待验收」单独标明。它与「收成窄条」是两个独立选项。
- **快捷新建**：点击新建或按 `Ctrl+Alt+N`（窗口内也可用 `Ctrl+N`），选择已有项目或填写实际存在的绝对目录，输入标题和详细需求；`Ctrl+Enter` 保存。保存后得到稳定任务标识；复制开工说明到已接入的 Agent，即可沿用这条任务。创建待办、复制说明都不会自动启动或派发 Agent。
- **项目聚焦与置顶**：聚焦某个项目可只看它的任务，退出聚焦回到所有项目；常用项目可置顶排列。项目置顶与窗口始终置顶是两个独立操作。其余项目默认按最近有更新的在前，可在设置 → 桌面 → 外观改为按名称首字母排序。放大镜旁的刷新按钮会立即重新读取任务状态和记录暂停状态。
- **搜索与最近变更**：点击项目选择旁的放大镜，或在看板内按 `Ctrl+F` 展开搜索。输入关键词后跨所有项目匹配标题、路径、任务标识、目标、需求、进展和用户意见，仍受当前状态筛选影响；清空后回到原项目范围，匹配的已完成项直接展开。「最近变更」按各项目最新变化、项目内任务更新时间排序，包含验收和人工反馈，临时展开任务；离开后保留原折叠和置顶偏好。它展示任务当前的最新变化，不是新增一套事件历史；所有检索在本机快照中完成。
- **任务详情与反馈**：查看完整需求、进展、计划步骤、Agent 标识、下一步、所需输入、交付物、项目路径和分支，并可复制。卡片显示步骤完成数（如「2/5 步」）。「Agent 上报记录」按字段展示最近 30 次实质上报；新 MCP 保留实际传入字段，早期记录可能经过规范化。你可以补充一条最新意见供 Agent 继续时读取；该字段不是聊天记录，提交新内容会替换旧意见，验收后仍可查看。开工说明也可展开手动复制。
- **暂停记录**：点底栏「暂停记录」后，下一次工具调用会收到「用户已暂停」，不读写任务，Agent 继续工作且不反复重试或轮询。点击恢复后，在下一个正常里程碑或新任务时重新尝试记录；不会主动唤醒 Agent，也不回补暂停期间的逐条操作。暂停时看板保留最后一次上报的状态。
- **归档与恢复**：在任务详情中归档不需要的任务（二次确认），或右键任务选「直接归档」；右键项目标题可「归档项目」，二次确认后把该项目在看板上的任务一次归档。
- **屏蔽项目**：右键项目标题选「屏蔽项目」并确认后，该项目从看板隐藏，之后在该项目中工作的 Agent 调用看板工具会被告知已屏蔽、不读不写。已有任务保留；在设置 → Agent 接入 →「屏蔽的项目」中可取消屏蔽。每个项目底部的「已归档」分组可展开查看并恢复本项目的归档任务。设置 → 桌面 → 整理中的归档中心可搜索、分页查看并恢复原任务，保留验收状态、人工意见和上报记录，不计为 Agent 更新；已验收的恢复项仍在原项目的「已完成」分组中。Agent 也可用 `task_archive` 恢复。
- **人工验收（可选）**：Agent 报告完成后，任务直接变灰并标记「未验收」，不再计入「等你处理」，也不弹通知。右键任务可「一键验收」；也可在详情中通过验收，或填写修改意见后退回待办；退回的任务会重新出现在 Agent 默认查询结果中。Agent 若在你验收前重新打开任务，卡片显示「已撤回验收」，下次完成后重新等待验收。旧版已完成任务保留原状态，不强制重新验收。
- **久未更新提示**：默认对超过 24 小时没有 Agent 实质更新的进行中、受阻任务显示提示；可关闭，或改为 1、4、8、24、48、168 小时。人工补充或验收不会冒充 Agent 的新上报，提示不会自动改变任务状态。
- **全局快捷键**：`Ctrl+Alt+K` 显示/隐藏浮窗，`Ctrl+Alt+N` 打开快捷新建；设置中可一并关闭。快捷键仅在 AgentKanban 运行时有效；退出后需要重新启动应用。
- **登录启动**：可在设置中选择 Windows 登录后启动浮窗，默认关闭；开启后默认只在托盘运行，不弹出窗口。它只启动看板，无需让 Coding Agent 随 Windows 启动。
- **系统通知**：任务变为受阻或需要你补充时，弹出 Windows 通知（浮窗在托盘运行即可）。通知会一直留在屏幕上直到你处理，点通知或「打开看板」显示浮窗，点「稍后」关闭；一次出现多条时合并为一条。可在设置中关闭。
- **自动归档**：已完成的任务（已验收或未验收）在若干天无变化后自动归档到所在项目的「已归档」，默认 7 天，可选 1、3、7、30 天或关闭；旧版未经过验收流程的已完成任务不会被自动归档。开启时每个项目最多保留最近 5 条已完成任务，更早的立即归档。
- **Agent 推进提示**：进行中且 Agent 在最近 30 分钟内上报过的任务显示「推进中」动效，所在项目标题和窄条的进行中计数也会标出。设置 → 桌面 → Agent 推进提示可选呼吸光点、旋转光环、跳动三点、心电波形、文字流光、卡片左侧流光、卡片呼吸或关闭，判定时长可选 10、30、60 分钟。它依据上报时间推断，不代表 Agent 此刻在线。
- **主题**：设置 → 桌面 → 外观可选跟随系统、浅色或深色；顶栏的月亮/太阳按钮一键切换深浅，并改为固定该主题。
- **语言**：设置 → 桌面 → 外观可选跟随系统、中文或 English，看板、托盘菜单和系统通知一并切换；部分来自本地程序的错误和更新详情仍为中文。安装程序按 Windows 语言自动显示中文或英文。
- **外观**：设置中可调字号（整体缩放界面，小 85% / 中 100% / 大 115%，也可在 80–130% 间微调）和不透明度（不透明 / 轻透 90% / 半透 75%，也可在 50–100% 间微调）。较大字号会相应提高窗口最小尺寸；连续修改按顺序保存，关闭设置不取消已提交的修改。
- **数据**：设置中可打开数据目录，或一键备份到 `backups/`（运行中也能得到完整副本）。连续备份生成独立文件，不覆盖已有副本。
- **同步健康**：设置 → Agent 接入展示本机最近调用、成功调用和成功保存时间，区分 MCP、CLI 备用入口、暂停与失败。打开页面或手动刷新即可读取，不增加 Agent 调用；这些历史结果不代表客户端此刻在线。需使用 0.5 MCP 才会产生记录。
- **软件更新**：设置 → 软件更新可检查 GitHub Releases、查看版本说明并下载更新，默认最多每天自动检查一次，也可开启自动后台下载。安装前验证签名、检查 MCP 是否占用并备份数据库；有占用时可稍后重试。详见[更新与发布](docs/UPDATES.md)。

四种任务状态保持不变。「执行完成」与「用户已验收」分别显示；MCP 不提供验收工具，验收由浮窗中的用户操作完成。Agent 标识来自它的上报，不代表身份认证或实时在线状态。

## 连接 Agent

首次接入可按以下顺序操作：

1. 打开设置 →「Agent 接入」，可运行本地自检，确认本机 `agentkanban-mcp.exe` 能启动并响应。
2. 在「接入客户端」中点击对应客户端的「一键接入」：写入 MCP 配置，并把精简同步规则加入该客户端的全局指令文件。首次修改的文件会先备份为 `<原文件名>.agentkanban.bak`。默认列出 Codex、Claude Code、DeepSeek Harness，「查看更多」中还有 Cursor、OpenCode、Antigravity、Hermes。配置检查会核对程序路径、参数、数据目录和启用状态；「已配置」仍需客户端重启后实际调用验证。
3. 重启该客户端，布置一个会修改文件的小任务，检查浮窗中是否自动出现对应记录。

一键接入写入的位置：

| 客户端 | MCP 配置 | 规则 |
|---|---|---|
| Codex | `~/.codex/config.toml`（或 `CODEX_HOME`） | `~/.codex/AGENTS.md` |
| Claude Code | `~/.claude.json`（备份后结构化合并，保留其他配置） | `~/.claude/CLAUDE.md` |
| DeepSeek Harness | `~/.dsh/cordis.patch.yml`（或 `DSH_HOME`） | `~/.dsh/AGENTS.md` |
| Cursor | `~/.cursor/mcp.json` | 无全局规则文件 |
| OpenCode | `~/.config/opencode/opencode.json` | `~/.config/opencode/AGENTS.md` |
| Antigravity | `~/.gemini/config/mcp_config.json`（旧版目录存在时同时写 `~/.gemini/antigravity/mcp_config.json`） | `~/.gemini/GEMINI.md` |
| Hermes | `~/.hermes/config.yaml`（或 `HERMES_HOME`）的 `mcp_servers` | 无全局规则文件 |

配置文件含注释等无法自动合并的写法时不会改动，展开「手动配置」复制对应片段自行合并。

**本地自检通过不等于客户端已连接。** 自检不能证明客户端已读取配置，也不能代替一次真实 Agent 工具调用。

仓库另提供 [Codex](examples/codex.toml)、[Claude Code](examples/claude-code.mcp.json) 和 [Cursor](examples/cursor.mcp.json) 静态示例，使用前需替换示例路径。

也可以用 PowerShell 7 生成含本机路径的独立示例文件：

```powershell
pwsh -NoProfile -File .\scripts\write-client-examples.ps1 -Executable "$env:LOCALAPPDATA\AgentKanban\agentkanban-mcp.exe"
```

如选择了其他安装位置，替换 `-Executable`。生成文件位于 `artifacts/client-config/`，仍需合并到需要使用的客户端。

入板规则写在 MCP 工具描述中。Codex、Claude Code 等会延迟加载工具说明，所以一键接入同时把规则写入全局指令文件，详见 [MCP 接入说明](docs/MCP.md#codex)。规则内容：会修改文件的任务自动记录，普通问答、只读审查和调研不记；不想记录时对 Agent 说「这个不用记到看板」。也可以指定标识，例如：

> 把「导出报告」功能加入 AgentKanban，task_key 用 `feature:export-report`。

后续会话优先按项目和关键词定向找任务，已知 `task_key` 时直接精读；接手前读取完整需求、计划及人工意见，继续原标识。同一任务由主 Agent 统一记账，子 Agent 返回结果，避免重复登记。「进行中」代表最后上报的状态；Agent 意外退出不会自动变成完成。

为控制上下文，`task_list` 支持 `query` 定向搜索，默认每页 5 条摘要；指定项目后不在每项重复路径，较长进展只显示摘要。精确 `task_key` 默认包括完成和归档记录，并返回完整需求。更新步骤可用 `step_updates` 只传变化项；修改已有任务必须带最新 `expected_updated_at`，并发创建撞名不会静默覆盖。详见 [MCP 契约](docs/MCP.md)及[同步规则](docs/AGENT_RULES.md)；另提供[可选 Skill](examples/agentkanban/SKILL.md)，它不能代替 MCP 配置，也不会自动安装到全局。

MCP 进程由客户端按需启动，GUI 没有运行时仍可写入。需要查看时再打开浮窗即可；无需一直运行浮窗，也无需设置 Coding Agent 开机启动。

若 **MCP 连接本身断开**，更新后的同步规则允许有本机命令执行能力的 Agent 使用同一程序、同一数据库的单次调用入口，在正常里程碑继续记录。重连后先查询原任务再合并，保留用户补充与并发版本检查。它不能自动修复客户端连接；若备用入口也不可用，Agent 应说明未同步，恢复后合并当前进度，不补造空档历史。升级后重新一键接入并让客户端加载新规则，详见 [断线处理](docs/MCP.md#mcp-断线时继续记录)。

## 从源码开发与构建

需要 Windows、Node.js/npm、Rust MSVC 工具链、Visual Studio C++ Build Tools 和 WebView2 Runtime。

```powershell
npm ci
npm run desktop:dev
```

`desktop:dev` 会先准备 MCP 可执行文件，再启动 Tauri 桌面窗口。`npm run dev` 只用于浏览器界面预览，不能验证托盘、置顶和本地持久化等桌面行为。

构建安装包：

```powershell
npm run desktop:build
```

该命令构建 release MCP 与桌面程序，并生成 Windows 安装包。Tauri 原始安装包位于 `target/release/bundle/nsis/`，整理后的交付文件位置以构建命令输出为准。运行安装包是单独动作，构建不会自动安装或修改客户端配置。无签名密钥时生成普通本地产物；供应用内更新使用的签名构建与 GitHub 草稿发布流程见[更新与发布](docs/UPDATES.md)。

更新本机已安装的版本（构建后覆盖安装到 `%LOCALAPPDATA%\AgentKanban`，数据保留）：

```powershell
npm run desktop:update
```

它会先构建，再关闭正在运行的浮窗、静默安装、核对安装的 MCP 版本与本次构建一致，并在浮窗原本开着时重新打开。加 `-SkipBuild` 直接安装 `release/` 中现有安装包（例如 `pwsh -NoProfile -File scripts/update.ps1 -SkipBuild`）。若有 Agent 会话正在使用 MCP，安装程序无法替换它，脚本会在改动前停止并列出进程；关闭这些会话，或加 `-StopMcp` 强制结束（这些会话的看板工具随之断开，需重开会话）。

验证真实 MCP 进程：

```powershell
node .\scripts\verify-mcp.mjs .\target\release\agentkanban-mcp.exe --report .\artifacts\verification\mcp.json
```

脚本使用系统临时目录的隔离数据库，覆盖协议握手、三个工具、状态流转、重复更新、分页、归档恢复、重启与四进程并发写入。成功后清理自己的测试数据；失败时保留路径和证据。详见 [验收记录与操作步骤](docs/VERIFICATION.md)。

## 数据与边界

```text
Coding Agent → 独立 stdio MCP 进程 → 本地 SQLite ← 桌面浮窗
```

GUI 与 MCP 共用 Rust 数据模块。浮窗退出后 MCP 仍可写入，重新显示时读取最新任务。窗口可见时每秒检查更新，隐藏时暂停刷新。

默认数据目录为 `%LOCALAPPDATA%\AgentKanban`，任务及界面设置保存在 `agentkanban.sqlite3`，WebView 缓存位于其下 `webview/`。SQLite 使用事务、WAL 和 5 秒锁等待处理多个进程写入；最终失败会返回明确错误。[SQLite WAL 说明](https://sqlite.org/wal.html)

`AGENTKANBAN_DATA_DIR` 可指定独立数据目录，适合测试；GUI 和 MCP 必须使用相同设置才能查看同一张看板。备份时先退出 GUI 并关闭客户端 MCP 进程，再复制完整数据目录。不要只复制仍在写入中的 `.sqlite3` 文件而遗漏 WAL。

项目名称默认取目录名，同一 Git 仓库的 worktree 归入同一项目，非 Git 目录按指定目录识别。`task_key` 与项目身份共同定位任务；同名目录和任务标题不用于去重。

界面英文与数字使用内置的 Manrope，代码与路径使用 Geist Mono（均为 SIL OFL，约 48 KB）；中文使用内置的 HarmonyOS Sans SC（Regular 与 Medium）。它的许可要求不修改字体文件、在软件中注明并附带协议，所以按原版 TTF 打包（约 16.5 MB，安装包因此增加约 10.6 MB），设置面板底部可查看声明和协议全文。字体与授权文件都在 `src/fonts/`，离线可用。

应用面向单机本地使用，不包含云同步、远程 Agent、日历提醒和插件市场分发。当前提供文字录入，不包含语音转文字、自动唤起或派发 Agent。久未更新提示只帮助查看已有记录，不提供 Agent 存活检测或后台催办。

[验收记录](docs/VERIFICATION.md) 记录各版本的实测范围并保留历史证据。本地 MCP 自检、客户端连接、Windows 注册项/窗口行为和用户日常体验分别记录；未执行的项目不标作通过。
